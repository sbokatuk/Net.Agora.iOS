## What's changed

`Net.Agora.Video.iOS`, `Net.Agora.Voice.iOS` and the twelve `Net.Agora.Extensions.*.iOS` packages
move to **4.7.0.1**: the native pins advance from AgoraRtcEngine_iOS and AgoraAudio_iOS 4.6.2 to
**4.7.0**, and the binding revisions start over at 1.

**If you also reference `Net.Agora.Signaling.iOS`, upgrade it to 2.2.6.4 at the same time.** See
below.

### Your app keeps a single aosl, and it has moved

The RTC pods now bundle `aosl` 1.3.16 where 4.6.2 bundled 1.3.5, and `AgoraRtcKit` 4.7.0 imports
five symbols 1.3.5 never exported. An app that references several packages keeps one
`aosl.framework`, so an app on Video or Voice 4.7.0 and a Signaling package older than 2.2.6.4 can
end up unable to load the engine. [`signaling-v2.2.6.4`](https://github.com/sbokatuk/Net.Agora.iOS/releases/tag/signaling-v2.2.6.4)
fixes that, and is released alongside this. `Net.Agora.Chat.iOS` is safe at any current version.

### What changed in the native SDK

The public headers only gained API, and nothing already bound here moved, so **the .NET API is
unchanged**. New upstream and not bound here, since this binding covers what the cross-platform
clients need:

- `setRemoteRenderRotation:rotation:` and its `Ex` form, with an `AgoraVideoRotation` enum.
- `AgoraRtcChannelMediaOptions.channelType` and `parameters`, `AgoraRtcEngineConfig.parameters`,
  `AgoraRtcVideoCanvas.rotation`, and metadata buffers on the video frame types.
- Error codes for video effects (1700 to 1707) and audio loopback (2007 to 2013), and two
  `AgoraFaceShapeArea` values.

### The frameworks changed

**Voice: `Agoraffmpeg` is replaced by `AgoraffmpegExtension`**, following the pod's own `RtcBasic`
subspec. It is still five xcframeworks. `AgoraRtcKit` no longer links ffmpeg at all: the engine loads
the extension itself, and falls back to a simple media player source if it can't.

**Voice: an app can't end itself with `exit` once an engine has existed.** After a
`SharedEngine` call, even one followed by `Destroy`, `Environment.Exit` and `exit(3)` never return:
an exit handler in `AgoraffmpegExtension` spins in `aosl_module_unregister`. Seen on the simulator
on every target framework. It doesn't affect apps that iOS terminates, which is how apps normally
end, or the Video package, which doesn't carry that framework. It is in Agora's code, so this
package can't fix it. If you need to, call `_exit` from libSystem instead.

**The four audio extensions now come from the `AgoraAudio_iOS` archive.** `Ains`, `Aiaec`,
`AudioBeauty` and `SpatialAudio` work with either RTC package, and from 4.7.0 the builds in
`AgoraRtcEngine_iOS` link `Agoraffmpeg`, which only the Video package ships. Taken from that archive,
any of them would stop a Voice app in dyld before `main`. The `AgoraAudio_iOS` builds link only what
both RTC packages carry, and a package test now holds them to that.

**`Net.Agora.Extensions.VideoEncoder.iOS` no longer ships `video_enc.xcframework`.** Agora removed
it from the archive, and `AgoraVideoEncoderExtension` no longer links it.

**The other eight extensions now need `Net.Agora.Video.iOS`.** They link `Agoraffmpeg` too, and
`AgoraAudio_iOS` has no build of them to take instead, so referencing one in a Voice app stops it at
launch. That is new: at 4.6.2 such an app still started, because the Voice package shipped
`Agoraffmpeg` then. Their package descriptions now say so.

### Samples

`Net.Agora.Sample.Voice.iOS` now joins as a broadcaster. It used to join as Audience, so it published
nothing, and two copies of it never saw each other.
