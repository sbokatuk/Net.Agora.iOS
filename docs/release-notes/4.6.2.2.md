## What's changed

**`Net.Agora.Voice.iOS` debuts**: .NET for iOS / .NET MAUI bindings for Agora's Voice SDK — the
"RtcBasic" subset of [`AgoraAudio_iOS` 4.6.2](https://cocoapods.org/pods/AgoraAudio_iOS), the same
RTC engine as `AgoraRtcEngine_iOS` built without the video pipeline. Five xcframeworks instead of
Video's six (no `video_dec` — the voice build of AgoraRtcKit links no video codec), for apps that
never show or send video.

`Net.Agora.Video.iOS` grows the same call surface: `switchCamera`, `renewToken:`, the audio-route
setters, `enableAudioVolumeIndication:smooth:reportVad:`, and the delegate callbacks for remote
audio/video mute, volume indication, token expiry and connection state
(`rtcEngine:connectionChangedToState:reason:` — also added to the Voice binding). Everything a
call UI needs that the thin first release deliberately left out.

**`Net.Agora.Signaling.iOS` debuts too**, at its own version **2.2.6.1**: hand-written bindings
for [`AgoraRtm_iOS` 2.2.6](https://cocoapods.org/pods/AgoraRtm_iOS) — Agora's Signaling (RTM 2.x)
SDK. Two xcframeworks (`AgoraRtmKit` + `aosl`), with the visionOS slices Agora ships for this SDK
stripped by the fetch script (the packages target iOS only). Scoped to the messaging core: client
config, login/logout, subscribe/unsubscribe, string publish, token renewal, and the delegate
callbacks for messages, connection state and token expiry. From this train on, each package
publishes at its own version line and a tag is just the train's label — see the release workflow.

> **Package versions are `<pod version>.<binding revision>`.** `4.6.2.2` is the 4.6.2 pods,
> binding revision `2`. The fourth component belongs to this repository and advances when the
> bindings or packaging change while the native artifact stays put.

## Contents

### Which package?

| Package | Native pod | Use it when |
| --- | --- | --- |
| `Net.Agora.Video.iOS` | `AgoraRtcEngine_iOS` | The app shows or sends video (also carries the full audio surface). |
| `Net.Agora.Voice.iOS` | `AgoraAudio_iOS` | Audio only — the smaller engine. |

Pick **one**: both pods ship a framework named `AgoraRtcKit`, so referencing both packages
collides at bundle time — mirroring Agora's own pods.

### The binding

Hand-written against the real `AgoraAudio_iOS` headers (Objective Sharpie cannot parse current
Xcode SDKs — see the Video binding's notes), under the `Net.Agora.Voice.iOS` namespace. Scoped to
what a voice app needs: create the engine, join/leave a channel, publish/mute audio, plus the
voice essentials the Video binding does not carry — audio-route control
(`SetEnableSpeakerphone` / `SetDefaultAudioRouteToSpeakerphone`), who-is-speaking volume
indication (`EnableAudioVolumeIndication` and its delegate callback), remote mute state
(`DidAudioMuted`), and token renewal (`RenewToken` / `TokenPrivilegeWillExpire`). The video entry
points the shared headers declare are deliberately not bound: the native voice engine cannot
perform them, so a binding that compiled them would only convert build-time certainty into
runtime error codes.

Two behavioural notes from driving the real 4.6.2 voice engine on a simulator, recorded in the
binding's comments:

- `setEnableSpeakerphone:` answers `-3` (not ready) before an audio session exists; use
  `setDefaultAudioRouteToSpeakerphone:` before joining.
- `enableAudioVolumeIndication:` answers `-2` (invalid argument) to the documented
  "pass 0 to disable".

Most apps want the cross-platform client instead:
[`Net.Agora.Voice`](https://github.com/sbokatuk/Net.Agora), which wraps this package and its
Android sibling behind one API — awaitable join, .NET events, speakerphone routing, volume
indication.

## Tests

The existing suites now run per package — everything still against the packed `.nupkg`:

- **Package tests** assert both packages' layout: binding assembly and native payload per target
  framework, every expected xcframework present (six for Video, five for Voice), payloads
  logically identical across target frameworks, iOS-only slices, manifests consistent with the
  slices shipped.
- **Simulator smoke tests** gained a package axis: the Voice legs prove the five frameworks load,
  the engine round-trips create → drive → destroy, and the audio-route/volume-indication surface
  crosses the bridge.
