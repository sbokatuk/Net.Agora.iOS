## What's changed

**Chat debuts**: `Net.Agora.Chat.iOS` **1.4.0.1** — a hand-written binding over
`Agora_Chat_iOS 1.4.0`, scoped to what a messaging client needs: `AgoraChatClient` (initialise,
sign in and out, renew the token), `IAgoraChatManager` (send, conversations), the message and
conversation model types, and the two all-optional delegates.

Note the pod: **`Agora_Chat_iOS`**, with underscores. The `AgoraChat` pod on CocoaPods trunk is the
abandoned 3.8.x Easemob line and is not this SDK. It is also the first product here whose `aosl`
does not come from its own archive — it declares `AgoraInfra_iOS` as a dependency, so
`build/fetch-chat.sh` downloads and checksums two archives rather than one.

**The RTC feature extensions ship.** Twelve new `Net.Agora.Extensions.<Name>.iOS` packages carry
the optional frameworks Agora bundles inside `AgoraRtcEngine_iOS` and exposes as CocoaPods
subspecs: AI noise suppression, AI echo cancellation, audio beautification, spatial audio, virtual
background, content inspection, video enhancement, face capture, face detection, video quality
analysis, and the software H.264/AV1 encoders. They are native payload only — the switch that
turns each one on is on `AgoraRtcEngineKit` — and they depend on neither RTC package, so an app
adds only what it turns on. `build/fetch-extensions.sh` stages them out of the archive
`build/fetch-video.sh` already downloads, so there is nothing new in `build/checksums.txt`.

**Both RTC bindings advance to 4.6.2.4** for the switches those extensions need:
`setAINSMode:mode:`, `setVoiceBeautifierPreset:`, `setAudioEffectPreset:` in both, plus
`enableVirtualBackground:backData:segData:`, the ClearVision options trio and
`enableFaceDetection:` in Video only — the voice build of `AgoraRtcKit` has no video pipeline for
those to act on. The option and enum types they take are bound alongside.

**The Interactive Whiteboard and Fastboard debut**, and they are the first products here with no
binary to fetch. Agora publishes every other SDK as a prebuilt `.xcframework` behind a
`download.agora.io` URL; netless ships both of these as CocoaPods *source* pods, so
`build/build-whiteboard.sh` and `build/build-fastboard.sh` build them: clone a pinned commit,
archive the repository's Swift package for both platforms, link the archived objects with
`libtool`, assemble the xcframework. No CocoaPods and no Ruby — the `Package.swift` resolves the
dependency graph.

That widens `build/checksums.txt`'s job past SHA-256-ing an archive, hence its second entry form:
a git source is pinned by **commit**, because a tag is a mutable pointer and netless has re-tagged
before. The clone finds the commit through the tag; the scripts verify the commit.

`Net.Agora.Fastboard.iOS` is the odd one out even among those: what it binds is not the SDK.
Fastboard is Swift, and although its public API is `@objc`-annotated, a Swift `@objc` class
registers under a mangled, module-qualified runtime name (`_TtC9Fastboard8FastRoom`) that a binding
would have to name literally and that changes with the module name. So `native/AgoraFastboardBridge`
— in this repository — wraps it in types with stable `@objc(...)` names, and that shim is what gets
bound. It also flattens the one call that cannot cross into Objective-C at all: `joinRoom`'s
`Result<WhiteRoom, FastRoomError>`, which becomes delegate callbacks.

Both packages carry resource bundles under **SwiftPM's own names** — the board's JavaScript and, for
Fastboard, its toolbar assets. Each library looks its bundle up by that exact string through the
module-bundle finder SwiftPM generated, so a tidier name makes the board render blank or the
toolbar come up as empty buttons, with no error either way. A binding package cannot ship a
`BundleResource` of its own, so they travel as plain content with a `buildTransitive` `.targets`
that re-declares them in the consuming app.

## Tests

The package tests grew a Chat row and a separate extension table — the extensions are held to the
framework *names* Agora gives them, since the mapping from a package's name to its framework is
not derivable (`VirtualBackground` ships `AgoraVideoSegmentationExtension`) and lives in
`build/fetch-extensions.sh`.

Whiteboard and Fastboard get tables of their own, because their packages are a different shape:
a static library rather than a dynamic framework, plus the resource bundles and the `.targets`
that installs them. Both halves are asserted — a missing bundle is the failure mode with no error
message.
